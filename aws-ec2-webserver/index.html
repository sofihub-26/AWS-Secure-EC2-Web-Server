02 / IDENTITY & ACCESS

Right access.
Right identity.

AWS Identity and Access Management (IAM) controls who can do what. Grant only the permissions needed for a task, and use roles—not embedded credentials—for AWS services.

01◉

Users

An identity for a person or workload that needs long-term credentials. Prefer IAM Identity Center for workforce access; don't create access keys unless a use case truly requires them.

IDENTITY
02▧

Groups

A way to assign the same permissions to multiple IAM users. Attach policies to a role-appropriate group rather than managing permissions user by user.

ORGANIZATION
03⬡

Roles

An identity with temporary credentials that a trusted person or AWS service can assume. An EC2 instance profile delivers its role credentials without storing keys on the server.

TEMPORARY ACCESS
04≡

Policies

JSON permission documents that specify allowed or denied actions and resources. The included sample allows read-only EC2 inventory actions; it does not grant instance control.

PERMISSIONS
✓
The least-privilege principle

Start with no access. Grant only the actions and resources required, review them regularly, and remove permissions when they are no longer needed.

03 / SECURE BY DEFAULT

Good security
is a habit.

A few careful decisions make this learning project safer and help build practices worth carrying into production.

View deployment guide ↗
✓
Protect the root account

Use root only for tasks that require it. Enable MFA, secure its recovery options, and do not create root access keys.

✓
Keep credentials out of code

Use the AWS Console or a named AWS CLI profile/SSO. Never paste access keys, passwords, or private keys into project files or source control.

✓
Limit network exposure

Allow inbound HTTP on port 80. Restrict SSH on port 22 to your current public IP with a /32 CIDR—not 0.0.0.0/0.

✓
Patch and remove resources

Keep the operating system updated. Stop or terminate resources you no longer need to avoid unnecessary exposure and charges.

04 / FROM ZERO TO LIVE

Build it. Secure it.
Ship it.

The setup combines AWS Console resource configuration with a Windows PowerShell SSH connection. Apache serves the deployed HTML, CSS, and JavaScript from the EC2 instance.

STEP 01◎

Set up IAM

Use a protected admin identity for setup. Create a least-privilege group, user only if appropriate, and an EC2 role only when the instance needs AWS API access.

IDENTITY FIRST
STEP 02▤

Launch EC2

Choose Amazon Linux 2023 and a small instance size. Create and securely store an SSH key pair; never share or upload its private key.

AMAZON LINUX 2023
STEP 03⬡

Lock down access

Create a security group with TCP 80 from the internet and TCP 22 only from your current public IPv4 address as a /32 CIDR.

MINIMIZE EXPOSURE
STEP 04⌘

Deploy the site

Connect from Windows PowerShell, copy the site files to EC2, and run the included script to install and start Apache.
